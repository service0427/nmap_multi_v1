# 🛡️ 식별자 1:1 순수 치환 및 동적 트리 순회 원칙 (SUBSTITUTION_CORE_RULES)

> **최종 개정일**: 2026-10-02  
> **핵심 철학**: "우리는 치환이 핵심이다. 원본에 없는 것은 절대 건드리지 않고, 원본에 있는 것만 1:1로 맞교환한다."

---

## 1. 3대 절대 원칙

### ① 순수 1:1 값 치환 (Pure Value-to-Value Substitution)
* **원칙**: `api_response.json`에 정의된 5대 원본 식별자(`SSAID`, `ADID`, `IDFV`, `NI`, `TOKEN`)와 일치하는 값이 패킷에 존재할 때만, 타깃 식별자로 1:1 맞교환(Swap)한다.
* **금지 사항**:
  * 원본 패킷에 존재하지 않는 키를 "혹시 모르니 채워넣자"는 식으로 임의 생성/주입(Injection)하는 행위 절대 금지.
  * (예: 안드로이드 패킷에 존재하지 않는 `usr.idfv`, `da-dv` 등을 강제로 생성하지 않는다.)

### ② 엔드포인트/필드 위치 하드코딩 금지
* **원칙**: "Protobuf 1.1에 있을 것이다", "길이가 16 이상이면 NI일 것이다" 같은 **위치 추정에 기반한 하드코딩을 절대 금지**한다.
* **사유**:
  * 과거 9월 22일 패치에서 `receiver/log`의 필드 1.1이 앱 버전 식별자(`mapmobileapps_Android_...`)임에도 불구하고, 길이가 16 이상이라는 이유로 NI로 덮어써서 훼손했던 치명적인 버그가 발생한 바 있음.
* **대응**:
  * 항상 **"값 대 값(Value-to-Value) 매칭"**을 원칙으로 하여, 트리의 어느 위치에 있든 값이 원본 식별자와 일치할 때만 교체한다.

### ③ 임의의 하이픈 제거(`replace("-", "")`) 자동 합성 금지
* **원칙**: UUID(ADID, IDFV)에서 임의로 하이픈을 벗겨내어 32자리 Hex로 만든 후 매핑 사전에 등록하는 행위를 금지한다.
* **사유**:
  * 120개 이상 세션 전수 검수 결과, 네이버 지도 앱은 항상 Google/Apple 표준 하이픈 포함 UUID(36자)로만 전송함.
  * 임의로 하이픈을 제거한 32자리 문자열을 매핑 사전에 등록하면, 다른 32자리 해시값(NI, MD5 등)과 의도치 않게 충돌할 수 있음.
* **대응**:
  * 하이픈 제거 형태가 필요한 특수 엔드포인트가 발견될 경우에만 `api_response.json`에서 명시적으로 할당하여 제어한다.

### ④ 클라이언트 실시간 식별자 자동 발견 및 등록 (Runtime Identity Auto-Discovery)
* **원칙**: 서버 `api_response.json`의 원본 식별자(특히 기기에서 동적 생성되는 `original.idfv`)가 서버 DB와 기기 간 불일치할 경우, 패킷 전송 시점의 실제 기기 식별자를 동적으로 감지하여 1:1 동적 치환 테이블에 즉시 등록한다.
* **사유**:
  * 안드로이드 기기의 네이버 지도 앱은 재설치나 초기화 시 기기 내부에서 IDFV를 자체 생성하여 전송함.
  * 서버 DB에 저장된 과거 `original.idfv`와 기기 실전송 `idfv`가 다를 경우 단순 고정 매핑만으로는 누락(Unreplaced Leak)이 발생함.
* **대응**:
  * 패킷의 전용 식별자 필드(`da-dv` 헤더, `iv` 쿼리, `usr.idfv` 등)에서 실시간으로 원본 값을 포착하여 `IdentityLookup`에 동적 등록(`register`).
  * 등록 즉시 해당 세션의 모든 헤더, 쿼리, JSON/Protobuf 트리를 대상으로 1:1 값 치환을 완벽하게 수행한다.

## 2. 동적 재귀 트리 순회(Universal Dynamic Tree-Walker) 규격

### 동작 방식
1. **입력**: `api_response.json` (또는 환경변수 `NMAP_ORIG_*`)의 원본 식별자 5종 및 타깃 식별자 5종 + **런타임 자동 감지된 실기기 식별자**.
2. **대상**:
   * HTTP Headers
   * URL Query Parameters
   * Request Body (JSON 디코딩 객체 또는 Protobuf 디코딩 객체)
3. **순회**:
   * 딕셔너리(`dict`)와 리스트(`list`)의 모든 계층을 재귀적으로 순회(`walk`).
   * 각 노드의 값이 원본 식별자와 일치하면 타깃 식별자로 1:1 교체.
   * `nlog_id`처럼 토큰이 포함된 복합 문자열은 부분 문자열(`orig_token in str_val`) 치환 적용.
4. **감사 기록**:
   * 치환이 일어난 모든 지점(`modifications.json`)에 `[URL, JSON Path / Protobuf Field, 원본, 타깃]`을 투명하게 기록.
